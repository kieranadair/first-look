# Executable analytical meaning

Research and implementation synthesis, 22 November 2026. This extends [the original evidence review](evidence.md) and [Terra integration](terra-integration.md). The implementation is First Look 0.2. This document describes conditional design patterns, not evidence of a measured productivity multiplier.

## The change in analytical architecture

A physical dtype and a NOIR role cannot say whether a column is a repeated order total, an additive line amount, a state, a rate, a running meter counter, or a circular direction. A useful automated analyst needs operational definitions as well as statistical profiles. First Look therefore makes a scoped semantic contract an input to analytical execution. Uploaded values remain immutable. There is no data lineage feature.

Every result is tied to the dataset fingerprint, parsing/field semantics, semantic revision, active source-row membership, focus and sampling assumption. A meaning edit creates a different context; old work cannot publish into it. Pins preserve the definitions that produced them. The same contract is available to the deterministic planner, chart compiler, Jev, Terra, local baselines, hosted TabPFN and evidence replay.

## Division of responsibility

**Deterministic Python** establishes finite recorded facts and executes the algebra. It checks types, membership, completeness, hierarchy exceptions, field dependencies, denominator domains, repeated values, gap budgets and context identity. pandas/NumPy/SciPy perform computations; Pydantic validates contracts; Pint validates relevant unit behavior. This is the authority for numerical evidence, not a statistical guess about business intent.

**Profiling** proposes names/quantity kinds and observational cadence; a repeated value can suggest a higher grain but cannot prove it. Proposed sums and entity averages require a confirmed definition. Existing row distributions remain useful without completing every tag. Exact search is bounded and its coverage is recorded.

**Jev** chooses among valid next views and can prioritize which unresolved question would unlock useful work. It does not answer a clarification, invent an option or modify the contract. Probability and margin thresholds control application abstention, not semantic truth. The four-decision investigation budget is preserved.

**Terra** can connect field descriptions, operational definitions, chart shapes and contradictions that a discrete decision model is not designed to generate. It proposes typed metadata hypotheses for human selection and evidence-linked checks for deterministic execution. The new semantic checks include denominator scope, averaging unit, reconciliation and gap handling. Its matched chart/table packet includes metric definitions, entity meanings, time policies, unresolved decisions and model protocol. Schedules, completeness and units cannot be established just by looking at values. Generated code never executes. Existing limits on images, packet length, calls and generated numerical prose remain active.

**TabPFN / local models** contribute held-out predictive evidence. They consume declared grouping and availability constraints. They do not write business definitions or supply missing factual observations. Residual/error diagnostics can suggest where further semantic review is useful; they do not automatically convert a hypothesis into a confirmed tag.

**The human** supplies the missing operational knowledge: what rows represent, what amount is recorded at which grain, which exposure weights are meaningful, which population a denominator refers to, whether event recording is complete, and what is available at prediction time. The interface asks focused questions and makes a declaration reusable; it does not require an exhaustive ontology form before exploration.

## Executable acceptance examples

`tests/test_semantic_engine.py` uses independent small oracles for: overlapping order/category incidence; partitioning line-sales shares; repeated order values and equal allocation including Other; average line vs average order; weighted price and recomposed revenue/unit; unknown vs structural-zero event days; irregular cumulative meters and resets; last snapshots; explicit NULL barriers; contextual hierarchies; offset/unknown-unit log rejection; post-aggregation transformations; declared group isolation; prediction-time availability; named metric intent; subset coverage; exact contract revision and export/recompute.

AppTest, the actual development agent API and Python browser assertions exercise native controls. Browser testing takes no screenshots, videos or traces. Controlled SDK transports validate integration boundaries; paid providers require the owner's later configuration and live evaluation. Numerical correctness of fixtures is not evidence of a universal semantic inference system, user-study benefit or a 100× productivity gain.

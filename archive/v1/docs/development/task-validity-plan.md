# Analytical tasks, availability and recording-process uplift

Build date: 24 November 2026. Implements the seven recommendations accepted after inspecting Prior Labs' official relational-prediction skill. The skill is design evidence, not an agent workflow to execute or a claim of validated model quality. Keep one source table, Python-only native Streamlit, hosted optional models and immutable source evidence.

## Execution plan

1. **Source fidelity:** inference recipe 2 preserves identifier strings and integers that cannot safely pass through floating point. Profile literal markers, numeric sentinel candidates, placeholder dates and conversion losses before coercion. Preserve explicit missing-token policy. Read old evidence with its original inference recipe; do not rewrite historical identities.
2. **Task contract:** a typed, dataset-scoped definition records question, descriptive/diagnostic/predictive purpose, unit, population description, target, decision time, anchor field, horizon and primary metric. Save explicit declarations under existing semantic metadata so revisions invalidate work without changing old contract defaults. Record the actual context/population and resolved task with model runs and provider evidence.
3. **Temporal availability:** typed field rules distinguish unreviewed information, declared knowledge at the anchor, timestamp-plus-delay availability and unavailable information. Record mutable/snapshot limitations and timestamp roles. Apply the same eligible projection to every model. Unknowns can support labelled exploratory diagnostics, not a validated future-use claim; explicit prospective tasks require reviewed availability. Text-derived predictors inherit their source rules.
4. **Recording process:** bounded, full-context temporal/group coverage tables, missingness contrasts, category presence and record counts. Preserve denominators, sample scope, selected-row context and incomplete-window warnings. Expose the same computed packet to models and in Challenge; model explanations do not establish completeness.
5. **Preflight:** share one deterministic preparation path between UI and fitting. Display target support, budget reductions, exact split membership, class balance, entity counts, predictor exclusions and unresolved assumptions before provider calls. Block structurally invalid tasks; retain useful descriptive exploration. Target-dependent predictor screens use training rows, not final held-out labels.
6. **Comparisons:** retain existing baselines and add metric-aware mean/median baselines, recorded predictions for all models and explicit observed comparison verdicts. Compare the same estimator on original/augmented text features separately from estimator differences. No winner selection by final holdout, significance claim or forced hosted-model superiority.
7. **Derived event tasks:** finite single-table recurrence/count recipes. Explicit entity/event identity, event and optional availability timestamps, past-only population and features, forward-only labels, complete-through attestation, nonoverlapping anchor windows, fixed final temporal holdout, original memberships and independent derived schema. At most six anchors, 10,000 derived rows and two prepared/evaluated experiments/context. No generated SQL, arbitrary expressions or automatic hyperparameter search. Use a separate Event lab when needed to keep the core Models page coherent.

## Integration and verification

- Understand shows source inspection; Meaning edits task/availability declarations; Models shows visible preflight; Text lab shows paired ablations; Challenge shows recording-process evidence; Event lab holds derived-task preparation and evaluation.
- All expensive event/model execution uses the existing worker manager, cancellation and context guards. Semantic/task edits invalidate dependent work; filter/return preserves reference state. Existing pins and saved comparison boards retain their original definitions.
- New model parameters and optional version-3 bundle extensions retain task, readiness, recording evidence and event artifacts. Data-free inspection is offline. Source-backed replay rebuilds derived event tables and memberships without re-fitting providers. Preserve old parsing and semantic hashes.
- Deterministic and model instruction boundaries are explicit: Terra proposes documented tasks/explanations and eligible checks; Jev judges narrow supplied statements/relevance; Python computes and enforces; humans attest unknown collection/availability facts. No live paid calls or effectiveness claim.
- Tests: exact large-ID oracle, literal-marker preservation, old-parser replay; temporal availability/unknown/snapshot cases; preflight/execution membership equality and no provider call on blocked inputs; full-context coverage denominators; matched text ablations; independently hand-calculated event population/features/labels, censoring and boundary cases; future-perturbation invariance of features; export/import/recompute/tamper rejection; native page flows.
- Run full pytest, Ruff, formatting, type checks, runtime-only packaging and development agent-API checks. Publish all intended files (including the newly installed Prior Labs skill/license/provenance) to `main` with an expected-parent lease; verify CI and byte agreement. Do not equate a GitHub push with observed Community Cloud deployment.

# Automatic analytical preparation · build plan

First Look 0.6.0 turns Understand/Meaning into progressive preparation. Uploads immediately receive a local draft; connected enrichment runs once when the visitor explicitly enables automatic connected preparation for that dataset. Local exploration remains available. No generated code, new runtime stack, database, or mandatory onboarding questionnaire.

## Implementation sequence

1. Add bounded preparation contracts, structural candidates, candidate metric bundles, exact evidence witnesses and explicitly hypothetical interpretation comparisons. Preserve computed/inferred/supplied/confirmed distinctions.
2. Add coherent Terra proposals from summaries, relationships, witnesses, optional plain-language notes and UTF-8 dictionaries. Jev reviews atomic support/scope/relevance questions; Python owns validation and application. Bound requests, payloads, cancellation and repeat execution.
3. Add one atomic, dependency-aware apply operation for selected declarations. Recheck source/parser identity and per-subject preconditions; preserve unrelated manual changes and reject conflicting stale proposals. Invalidate dependent work once. Record selections and supporting evidence in the semantic ledger.
4. Add portable, explicitly reviewed semantic templates. Match unambiguous field names and physical families, remap identities, recompute structural preconditions and expose drift. Never transfer observation completeness, historical availability, model splits or held-out outcomes.
5. Put a compact preparation overview in Understand and a dedicated Preparation work area for reviewing bundles, consequential questions, notes/documents, templates and the preparation record. Keep detailed Meaning controls; show readiness by requested analytical capability, not an ontology-completion score.
6. Feed accepted meanings and task context into the existing metric/chart/discovery paths. Recommend useful starting views using supported operations. Foundation-model experiments remain downstream of task validity and a fixed evaluation protocol.
7. Include preparation records in checksum-covered evidence with explicit privacy marking, data-free inspection and no provider calls on replay. Add regression tests for numerical alternatives, transaction rollback, stale edits, dependencies, template drift, provider boundaries, budgets, native UI and replay. Run lint, types, tests, runtime smoke and packaging; commit the completed build.

## Product acceptance

- A new table produces a useful review without API keys or manual ontology editing.
- One supplied explanation can produce several related, separately inspectable proposed changes and one application transaction.
- All actual business confirmations require an explicit selected-bundle action. Model probability cannot grant a permission.
- Ambiguities are ranked by current task relevance, affected operations and observed differences between stated alternatives. Equality on one dataset does not establish equivalence.
- Connected preparation never repeats on a rerun, cannot overwrite a concurrent edit, and degrades to the local draft on provider failure.
- Templates remain proposals; new structural exceptions and completeness never inherit old attestations.
- UI preserves evidence next to the decision and offers immediate descriptive exploration while unrelated questions remain open.

Research foundations: contextual annotation (Sato), ambiguity surfaced at its point of consequence (DataTone), hard constraints versus preferences (Draco), existing summarizability/task-validity research mappings, and TypeSafe's atomic-judgment/software-control guidance. These motivate design; no measured productivity multiplier or live-provider effectiveness is claimed.

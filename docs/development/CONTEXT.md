## Product and architecture

First Look is a Python-only open-source visual investigation workbench. Eleven visible native Streamlit work areas and a hidden linked Inspect finding detail route: Understand, Meaning, Explore, Findings, Compare, Models, Text lab, Event lab, Challenge, Evidence, Judgments. The original `discover.py` path remains the Findings page. Python 3.12, Streamlit 1.67. Runtime requirements are pinned; this release adds no dependencies. No SaaS/account/database layer, local foundation-model weights, authored frontend or data lineage system.

`firstlook/semantic_contracts.py` defines the scoped semantic model. `firstlook/semantic/profile.py` performs bounded exact structural discovery and heuristic proposals; `model.py` validates/commits/imports declarations; `policy.py` evaluates operation permissions; `planner.py` shares metric plans and bounded metadata packets; `engine.py` executes the typed algebra; `checks.py` compares definitions. Existing numerical discovery and diagnostic views remain available while business decisions are unresolved.

Dataset records include a semantic model scoped to the exact source fingerprint and parsing/physical-field layout. Meanings, metric definitions, entities, contextual hierarchy/membership evidence, time policies, assertions and focused clarifications participate in context identity. Changes invalidate dependent analyses and worker publication; source values are immutable. Pins retain the original context, field semantics and semantic-contract snapshot. Version 3 evidence bundles export the model, decision ledger, coverage, companion relationships and explicitly validated multi-context comparison boards. Version 1/2 bundles remain inspectable; plans without a recipe version report `legacy-recipe-inspection-only` instead of silently substituting the repaired algorithms.

Typed metrics: row and distinct-entity counts, sum, recorded/entity means and median, weighted mean, sum per distinct entity, ratios with explicit population scope, latest entity snapshots, cumulative-counter increments, degree-based circular means, and permitted post-aggregation transformations. Repeated entity values require constancy; overlapping entity totals need explicit full-credit/equal observed-membership attribution. Other and temporal summaries recompute source components. Sums of states/rates/counters and invalid log/unit domains are blocked.

Observed cadence is distinct from declared schedule. Structural zero requires confirmed event recording, coverage and last-complete date. Carry/interpolation is bounded and process-specific; explicit NULL is a barrier. Gap filling is disabled for arbitrary selected rows lacking scoped coverage. Counter resets remain missing and increments belong to the ending reading. No interval apportionment, holiday calendar or general missing-data imputation.

Jev receives task-specific evidence and answers atomic applicability, intent, relevance, note-evidence, text-coding and claim support/scope questions. Python owns ranking, unresolved outcomes, execution and eligibility. Terra receives definitions, metadata, matched visual/table evidence and model protocol; it can propose typed semantic hypotheses and text-feature questions, eligible checks and cited prose. Neither changes facts or permissions automatically. Models respect declared entity holdout and predictor availability, including post-outcome categories. No joint group/time protocol or causal interpretation.

## Task validity and event layer

`analytical_tasks.py` defines descriptive/diagnostic/prospective tasks and time-of-knowledge rules under existing semantic metadata (`search.analytical_task`, `search.availability`). Their revisions use the existing context invalidation and human ledger. Known-at-anchor rules bind to decision-time/anchor basis and require review if it changes. Unreviewed or undocumented mutable predictors remain diagnostic assumptions; prospective tasks exclude them. Timestamp-plus-delay checks exclude a late/unknown field consistently for every provider. Population descriptions document intent and do not execute filters. Source field semantics, availability and mapped basis carry into text-derived features.

`model_protocol.py` is the single preparation path for preview and execution. Target-dependent screens use training rows. Preflight exposes exact partitions, class support, availability exclusions, incomplete outcome windows, label purging and budget reductions. Models records this alongside all comparator predictions, including mean/median references. Diagnostic estimators are not selected by final-test performance; comparison verdicts report observed differences. Text feature results expose same-estimator ablations separately.

`source_inspection.py` counts literal marker/sentinel/date candidates before coercion. Inference recipe 2 protects identifier strings, leading zeros and integer strings beyond floating-point precision. Old evidence without an inference version loads recipe 1, preserving historical contexts, including its Parquet missing-token behavior. Exact supplied bytes validate saved source inspection. Do not silently migrate old artifacts to new parsing rules.

`recording_process.py` computes full-context temporal/group coverage and category representation with explicit denominators and undated rows. It is an eligible discovery candidate, finite challenge, dedicated Challenge perspective and compact provider evidence. Large missingness contrasts are engineering review triggers, not proof of a recording mechanism or leakage. Models cannot infer complete coverage or historical versions from these patterns.

`event_tasks.py` supports recurrence/count tasks over one event table, at most six nonoverlapping anchors and 10,000 derived entity-anchor rows. Explicit coverage/availability attestations precede preparation. Past-only populations and features use available events; forward labels require complete windows. Unassignable entity/event/time rows block preparation rather than creating false negatives. Unknown knowledge times exclude events from historical features but retain observed forward labels. Repeated IDs are deduplicated only with consistent entity/event time. The last complete anchor is held out, earlier label windows plus the attested outcome reporting-delay bound end by that boundary, and each frozen task is evaluated once. This is later activity of observed entities, not unseen-entity transfer; the source group constraint is not mutated. Two preparations and two event evaluations/context use existing workers and stale guards.

Event lab separates population/label and model-comparison views. Exact source memberships, derived bytes/schema/context, task specification and optional models travel in `analysis/event-tasks.json`. Source-backed replay rebuilds them; data-free replay inspects recorded values without provider calls. Task/availability controls live in Meaning; source inspection in Understand; readiness in Models; recording diagnostics in Challenge. Event runs participate in context invalidation, filter/return preservation and prepared-download hashing. No added runtime dependency, generated SQL or local weights.

## Typed-judgment workflow

Use the installed TypeSafe skill and current live documentation for integration work. `judgments.py` holds versioned contracts, probability validation, recorded outcomes and conservative input budgeting; `judgment_catalog.py` centralizes question templates. `providers/typesafe.py` calls the real SDK's mixed Noul/Choice/Score interface. Legacy Choice records remain supported; new integrations use `.judge()`. Transport/invalid-answer failures are errors, never negative judgments. `recommendations.py` combines model relevance with computed complementarity, support and cost; weights and thresholds are engineering defaults, not learned calibration.

`question_workflow.py` separates prepared intent from explicit execution. The Findings panel permits correction, revalidates scope and records the actual executed interpretation. `clarifications.py` computes metric dependency counts, selects verbatim supplied note passages without confirming business meaning and calculates hypothetical quantity assumptions on isolated copies. Meaning's fifth tab is What if?.

`text_features.py` freezes concrete binary definitions, codes at most 240 rows × six features with distinct missing/overlong/unresolved states, deduplicates repeated text while preserving original memberships and validates all saved values against recorded answers. Whole-plan input preflight happens before coding. Derived modeling tables receive their own fingerprint/schema and original-row mapping. Baseline and augmented models share exact train/test memberships, declared entity groups and predictor availability; coded unknown states are explicit categories. Terra sees at most eight text-only proposal examples without targets. No final-holdout feedback loop exists. Source text requires separate per-dataset sharing permission in addition to external-analysis permission.

`claim_review.py` retains original Terra output and shows bounded atomic claims with evidence citations, Python reference/numeric/causal guards and optional independent Jev support/scope judgments. Model-supported prose remains interpretation. `judgment_lab.py` gathers records, compares definitions/models/state and exposes seven developer-labelled routing cases. The Judgments page is inspection-first and never calls a provider just by opening it. The Text lab supplies definitions, request preview, coverage, cohort preview, CSV download and matched evaluation in separate visible stages.

`state.py`, `ui/runtime.py` and evidence export preserve context invalidation, original investigations on filter/return, worker cancellation and stale-publication guards. New optional version-3 files record judgments, recommendations, question history, workflow and text features. Data-free inspection does not call providers. Exact model inputs can contain private text even without the original file. Prepared Evidence downloads are invalidated when any new ledger, text run, model evaluation or scenario changes.

A session-owned job manager runs expensive work outside reruns. Discovery retains twelve automatic findings; interactive working views are bounded at eighteen, with standalone pinned snapshots. Existing global/per-session worker limits and provider call budgets remain.

## Exploration and comparison layer

Read [exploration uplift report](exploration-uplift.md) and the linked design before extending it. The Section II chapter review is [research history](../research/few-part-ii-review.md); do not reimplement its completed suggestions.

`exploration_contracts.py` defines tasks, finite perspective coverage, separate numerical/display scope and cohort/reference contracts. `comparison.py` computes row/entity closure, explicit denominator/allocation populations, shared domains/category identities, full-source quantile/CDF effects and recorded-model slices. `exploration.py` owns seven finite recipes: group shape, density, influence, concentration, categorical facets, histogram sensitivity and temporal context. New calculations carry recipe version 2; no generated expressions/code execute.

Preview selection preserves the investigation, model and allowances. Compare computes two validated child contexts; only explicit filtering changes the working population. Return to reference restores the anchored investigation. Publication rejects stale cohort revisions even if the base context has not changed. Counter interval endpoints cannot be silently unioned into a row cohort. Comparison boards retain dataset/semantic snapshots and recorded model protocols across later meaning edits; original bytes and each saved parser/meaning scope govern recomputation. At most three saved boards plus an active board; comparison children share the 18-view working allowance.

Metric top-K ranks the requested quantity before creating Other. Group comparisons freeze identities/remainder membership and compare by keys. ECDF compression respects tied mass and certifies vertical error; reported quantiles, CDF distances and threshold queries use source values. Native/review renderers share endpoint extensions with no invented source members. Scatter statistics, visible points and review reductions have separate scopes. Conditional center/spread renders existing quartiles and screens variance-only patterns. Geometry guards exclude unsupported scalar prediction targets.

Explore, Compare and Models are separate pages under the user's latest instruction. Keep related evidence together; use compact headers, adjacent panels, visible definitions/support and short workflow guidance. Configuration can move into a secondary control after computation. Essential analytical views do not live in expanders. Models displays related diagnostic pairs and reuses recorded holdouts; no brush triggers a model refit. Python-only and native Streamlit/ECharts remain requirements. The user authorized screenshots for UI review on 23 November 2026; the earlier screenshot prohibition is superseded. Automated browser smoke scripts still avoid image capture.

Jev can prioritize a missing eligible distribution task using its existing decision call. Terra receives coherent companions and can review one selected/reference board per investigation, propose bounded child-context checks and synthesize them. The deterministic core remains complete without keys. Live provider effectiveness, Cloud availability and human productivity are unmeasured.

### Current chart policy

The finite catalog now has thirteen templates, including frequency polygons, saved-quantile deviations and validated treemaps. `visualization/layout.py` controls square inner scatter/density geometry through native dimensions/media options; it does not equate unrelated data units. `compiler.py` and `review_assets.py` share encoded quantities, numerical domains, category order, collision-resolved group colours and colour limits. Histogram bars preserve recorded numeric intervals. Magnitude/facet bars include zero; only correlation-summary dots get a fixed −1..+1 domain. Signed residual heatmaps diverge around zero; counts remain sequential. Range boxes declare min/max whiskers. Observed/predicted diagnostics use identity and residual diagnostics use zero.

`visualization/composition.py` permits original amount binding only for the engine's validated complete concentration recipe. `ChartSpec.value_field` preserves the distinction between cumulative share and original amount; changing the representation never overwrites the result. Pins preserve that chart contract. Treemap zero parts remain in the table, and the initial overview choice uses a visible editable panel row budget, not a purported Few threshold. Two-group frequency polygons use common full-source edges and within-group proportions. `visualization/quantiles.py` displays only saved full-source quantile differences against probability, with a horizontal zero reference and no invented curve or source membership. Compare shows this third chart alongside the two population views; group-shape results expose it as a companion.

`visualization/guidance.py` separates ten Python-owned invariants from seven conditional preferences. Jev receives atomic eligible-choice guidance; Terra receives visual-hypothesis and supported-check guidance. Both real adapters transmit a compact versioned `chart_policy` and record its request state/instructions. Preferences do not grant execution permissions. The rule registry appears in chart safeguards. Controlled SDK assertions verify actual outgoing requests; they are not live-model validation.
